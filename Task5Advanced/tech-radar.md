# Расширенный технический радар «Будущее 2.0»

Горизонт: целевая архитектура на 3 года.  
Статусы: **Adopt** (внедрять), **Trial** (пилот), **Assess** (оценка), **Hold** (не развивать / выводить).

---

## 1. Архитектурные паттерны

| Паттерн | Описание | Статус | Комментарий |
|---------|----------|--------|-------------|
| Событийная архитектура (Event-Driven) | Домены обмениваются фактами через шину событий | **Adopt** | Целевая модель интеграции |
| Data Mesh | Децентрализованные data products с доменными владельцами | **Trial** | Пилот в финтехе и пациентском потоке (0–6 мес.) |
| Антикоррупционный слой (ACL) | Изоляция легаси от новых доменов | **Adopt** | Мосты для Camel и DWH на период миграции |
| Domain-Driven Design | Ограниченные контексты, агрегаты, события | **Adopt** | Основа декомпозиции |
| Lakehouse | Хранение и аналитика на объектном хранилище + SQL-движок | **Trial** | Пилот витрин KPI |
| Self-service BI | Портал самообслуживания для бизнес-пользователей | **Trial** | Цель на 12 мес. |
| CQRS | Разделение команд и проекций чтения | **Assess** | Точечно в высоконагруженных доменах |
| Strangler Fig | Постепенная замена легаси | **Adopt** | Стратегия миграции DWH |
| Мультирегион / Data Residency | Локальное хранение по регионам | **Assess** | Перед выходом в 2–3 региона |
| Монолитный корпоративный DWH | Единое хранилище с бизнес-логикой | **Hold** | Вывод к 36 мес. |
| Синхронная шина ESB (hub-and-spoke) | Точечные интеграции через Camel | **Hold** | Только мост совместимости |

---

## 2. Платформы и инфраструктура

| Технология | Назначение | Статус | Комментарий |
|------------|------------|--------|-------------|
| Облако (IaaS/PaaS) | Вычисления, сети, К8s | **Adopt** | Основа целевого ландшафта |
| Apache Kafka / managed streaming | Шина доменных событий | **Adopt** | Пилот 0–6 мес., prod 6+ мес. |
| Schema Registry | Версии контрактов событий | **Adopt** | С первого пилота |
| Объектное хранилище (S3-совместимое) | Data lake, бэкапы, state Terraform | **Adopt** | |
| Kubernetes | Оркестрация микросервисов | **Adopt** | Финтех, ИИ, интеграции |
| SQL Server 2008 (on-prem DWH) | Легаси-хранилище | **Hold** | Read-replica → вывод |
| Apache Camel | Легаси-шина | **Hold** | ACL → вывод к 24–36 мес. |
| On-prem серверная стойка | Старое железо | **Hold** | Сокращение по мере миграции |
| Terraform + GitLab CI/CD | Инфраструктура как код | **Adopt** | Уже в программе трансформации |
| Managed Flink / Spark Streaming | Потоковые витрины | **Trial** | Этап 6–18 мес. |
| Feature Store (ML) | Версии признаков для ИИ | **Assess** | Монетизация AI-функций |

## 3. Инструменты данных и аналитики

| Технология | Назначение | Статус | Комментарий |
|------------|------------|--------|-------------|
| Каталог данных (Data Catalog) | Lineage, метаданные, glossary | **Trial** | Этап 6–18 мес. |
| dbt / SQL-трансформации | Сборка доменных витрин | **Trial** | В доменах-пилотах |
| Power BI | Отчётность | **Trial** | Постепенная замена кастомизаций порталом |
| Портал самообслуживания (custom) | Витрина KPI, конструктор отчётов | **Trial** | Без PHI |
| Debezium (CDC) | Репликация из DWH в события | **Adopt** | Мост миграции |
| Airflow / оркестратор batch | Ночные загрузки (сокращаемые) | **Assess** | Только где нет streaming |
| PowerBuilder | UI операторов клиник | **Hold** | Замена веб-порталом |
| Ручной ETL в DWH | Трансформации в SQL Server | **Hold** | Не расширять |

## 5. Практики и операции

| Практика | Описание | Статус |
|----------|----------|--------|
| Инфраструктура как код | Terraform, удалённый state | **Adopt** |
| CI/CD для данных и инфраструктуры | GitLab Pipelines | **Adopt** |
| Наблюдаемость (метрики, логи, трейсы) | Prometheus, Grafana, OpenTelemetry | **Trial** |
| Управление качеством данных | DQ-правила в доменах | **Trial** |
| FinOps | Контроль облачных затрат | **Assess** |
| Ручные правки в prod DWH | Hotfix в stored procedures | **Hold** |
